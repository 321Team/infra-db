# infra-db
321Team FDS 프로젝트의 PostgreSQL 외부 VM 구축·설정·운영 형상관리 저장소. P1-DB-01의 설치 자동화, DB·역할·접근제어 설정, 백업·복구 절차 및 검증 자료를 관리한다.

- [P1-DR-01 Backup / Restore Runbook 검토안](docs/P1-DR-01_BACKUP_RESTORE_RUNBOOK.md): 기존 복원 증적, 새 실행의 전제·중단·복구, 비공개 dump 인계 기준.

## 변경 검토 및 승인 절차

[리뷰·Lead 정책](docs/REVIEW_POLICY.md)은 병합된 중앙 정책을 적용한다. P1-DB-01의 담당과 이권욱의 최종 병합 역할을 유지한다.

1. Lead는 `p1-db-01/<작업명>` 브랜치에서 PR을 작성하고 연계 티켓, 변경·영향·복구, 전체 HEAD SHA, 검증·증적·잔여 작업을 기록한다.
2. DB 설치 자동화·역할/접근제어·SQL·실행 설정·테스트 등 코드 또는 혼합 변경은 작성자 외 적격 검토자 1인 이상이 해당 HEAD를 검토한다. AI 보조 점검을 독립 승인으로 표시하지 않는다.
3. 문서·증적 기록만 변경하면 해당 Lead가 검토·병합을 판단한다. 본인의 PR에 자기 GitHub APPROVE를 요구하지 않는다. fds-project-evidence의 모든 PR은 독립 리뷰가 필요한 예외다.
4. 새 commit은 해당 변경과 영향 범위만 재검토한다. 이권욱은 최종 HEAD, 코드 변경에 필요한 독립 검토, 필수 검사와 미해결 차단사항을 확인해 수동 병합하고 승인 HEAD·병합 commit을 기록한다.
5. 실제 DB 서버 반영·백업/복구·영구 반영·AC 인수·종결은 책임 Lead가 대상·검토된 SHA·선행조건·성공/중단·복구와 실제 증적을 근거로 판단한다. 코드 병합과 운영 실행은 별개이며 단계마다 독립 서명을 추가 요구하지 않는다.

## 적용 방식

main 직접 push·force push·자동 병합을 금지하고 PR을 사용한다. 이 문서는 운영 통제이며 실제 GitHub 보호 설정이 활성화됐다는 뜻이 아니다. 계정·팀 권한, branch protection/ruleset은 이 변경에서 조정하지 않는다.

AC·DB 접근제어·비밀정보 비저장·백업/복구 검증은 유지한다. 문서 편입이나 코드 병합만으로 Runtime PASS·인수·티켓 완료를 선언하지 않는다.
